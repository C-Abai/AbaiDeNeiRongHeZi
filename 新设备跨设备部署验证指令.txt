# 内容盒子 PWA — 新设备跨设备覆盖部署验证指令（2026-11-05 定稿版）

你是新设备上的 WorkBuddy 助理。本次目标：验证「在新设备部署能否覆盖原链接 …24323 且不新建链接」。
本版为最终方案（会话根 genie + 不传 appId），并新增「验证失败 → 切换新链接」的处置分支（见第 8 节）。
配套说明见仓库 HANDOVER.md §5c / §5d。

⚠️ 前次测试失败的根因已定位：genie 必须放在 **WorkBuddy 会话根目录**，不是「项目文件夹的父目录」。本指令已更正该位置。

请严格按以下步骤执行，最后向用户汇报结果，并完成清理。

================================================================

- 确认本设备登录的 WorkBuddy 平台账号，与创建 …24323 的是「同一个账号」。
  - 若不是同一个账号 → 你无权覆盖，**立即停止**并告知用户「账号不符，无法覆盖」，不要继续。
- 本任务需「可自动执行」的代理模式（Agent 模式）。

================================================================
## 2. 确定 WorkBuddy 会话根目录（关键！）
- 会话根 = WorkBuddy 为「本次这个任务」创建的文件夹，通常形如：
  C:\Users\<你的用户>\WorkBuddy\<某日期时间>\
- 把克隆下来的项目文件夹，作为**子文件夹**放进会话根，例如：
  C:\Users\<用户>\WorkBuddy\<会话根>\pwa-content-app\
- 下一步的 genie 文件要放在**会话根这一层**（和 pwa-content-app 同级），不是项目里面。

================================================================
## 3. 创建绑定文件（放在会话根目录）
在「会话根目录」创建两个文件（与 pwa-content-app 同级）：

文件 A：<会话根>\.wbapp_jFiM5Y7b9RmUulYAimy36N.genie
----------------------------------------------------------------
appId: wbapp_jFiM5Y7b9RmUulYAimy36N
name: 内容盒子
localDir: <会话根>\pwa-content-app
appType: web
entryHtml: index.html
----------------------------------------------------------------
（把上面 localDir 改成你本机项目的实际绝对路径）

文件 B：<会话根>\.workbuddy\applications.yaml
----------------------------------------------------------------
applications:
  - name: 内容盒子
    locator: wbapp_jFiM5Y7b9RmUulYAimy36N
----------------------------------------------------------------

⚠️ 常见错误：把 genie 放进 pwa-content-app\ 里面，或放进「项目父目录」但该父目录 ≠ 会话根 → 工具在会话根扫不到 → 静默新建链接。务必放在会话根。

================================================================
## 4. 部署（覆盖测试）
调用部署，参数如下：
- directory = <会话根>\pwa-content-app（项目文件夹）
- domainPrefix = content-box-24323
- entryHtml = index.html
- language = static
- userAskedToPublish = true
- **不要传 appId**（工具应在会话根扫到 genie，自动命中现有应用）
  （11-03 的旧结论「显式传 appId 即可」已被 11-04 真实新设备测试推翻，勿再使用）

================================================================
## 5. 验证（核心）
部署返回后检查：
- 返回的 shareLink / 链接是否仍是 …24323？
- 是否新建了任何其他链接（如 …71596、…87884 或任何新数字后缀）？
- 返回的 appId 是否为 wbapp_jFiM5Y7b9RmUulYAimy36N？

成功标准：原链接 …24323 不变 + 没有新建任何链接。
失败标准：出现了新链接，或 shareLink 不是 …24323。
无论成功失败，都请在汇报中记录：返回的 appId、完整 shareLink（含 sharecode 门禁参数）、
以及返回结果里的 genieFilePath（它揭示了工具实际认定的会话根，是判断根因的关键证据）。

异常处理：
- 若报错 SITES_START_FAILED（沙箱冷启动超时，非代码问题）：重试一次即可。
- 若失败且指向了现有 appId，原链接 …24323 可能暂时打不开 → 立刻从同一目录再部署一次恢复。
- 若生成了新链接：**不要 unpublish、不要下线**（用户可能决定改用新链接，见第 8 节）。
  只记录其完整地址、appId、sharecode 并交回用户决策；同时确认原链接 …24323 仍可访问、未被下线。

## 7. 清理（仅在「验证成功」且用户明确不需要保留测试环境时执行）
- 验证成功：可删除本次创建的克隆目录、genie、.workbuddy\ 与临时目录。

**不要删除**任何你没创建的文件，也不要动服务器上的生产链接 …24323。
生产链接 …24323 必须保持原样、可访问、不下线。

================================================================
## 8. 验证失败时的处置（Plan B：改用新链接，旧链接不下线）
用户既定决策：若本次仍生成新链接，则以后用新链接部署；**原链接 …24323 暂时不下线**，
并在原链接上发布「新链接 + 重新打包的新 APK」迁移公告，让老用户平滑更新。

> **📌 执行迁移请直接读 `路径二-新链接替换原链接执行手册.md`**（Phase 0→4），
> 代码/内容替换用 **`tools/migrate_to_new_link.py`** 一键自动完成并自检。
> **🔒 人类闸门（不可跳过）**：在把新链接作为「替代原链接」对外、或在原链接发迁移公告指向它
> **之前，必须先向用户汇报情况、回答提问；只有用户明确说「同意上线新链接」后才许发布**。
> 任何「先看看」「你觉得呢」都不是授权。

助手在失败时须做：
1. 记录并回报：新链接完整 URL（含 sharecode）、新 appId、新 genie 文件路径。
   **STOP：先回报，绝不在未获用户「同意上线新链接」授权前发布新链接或发迁移公告。**
2. **不要** unpublish 新链接、**不要**下线或改动原链接、**不要**删除新 genie。
3. 提醒用户把新 appId / 新链接 / 新 sharecode 写回仓库 HANDOVER.md 与本文档，
   否则以后无法稳定覆盖新链接。
4. 后续部署关系说明（用户常问，务必讲清）：
   - GitHub 仓库**不绑定任何链接**；绑定关系 = 平台账号 + 本地会话根的 .wbapp_<appId>.genie。
     哪个会话根放哪个 appId 的 genie，就覆盖哪个链接。
   - 一个工作区/会话只能有一个 app 链接。要同时维护新旧两个链接，需开**两个 WorkBuddy 任务窗口**，
     分别放旧 appId 与新 appId 的 genie。
   - **旧链接已解耦 GitHub**（自 1ea3f0a 起 `USE_GITHUB_SYNC=false`）：它只读自己部署的快照，
     往 GitHub 覆盖 content.json **不会**再影响旧链接访客。旧链接改内容 = 用解耦版重新部署旧 appId；
     日常普通更新仍可进原链接后台改完发布（后台本就不读 GitHub）。
   - 若走路径二生成新链接：迁移工具 `migrate_to_new_link.py` 会把【新链接】的 `USE_GITHUB_SYNC`
     改回 true 并推送 GitHub，届时「覆盖仓库 content.json」只同步【新链接】，与旧链接互不影响。
   - 界面 / 代码层改动只能重新部署对应 appId；旧 APK 内硬编码 host 无法远程改，只能重新打包。
   - **v87 起 content.json 已瘦到约 20KB**（18 处图片外置到 `assets/img-*.jpg`，17 张图约 927KB）。
     clone 或下载部署包时**务必确认 `assets/` 目录一起带上**，否则所有封面 / 壁纸 / 图标 404。
     图片路径里写死了 `?sharecode=AK6QIELR67`，迁移到新链接时用
     `python tools/externalize_images.py --sharecode <新码>` 一键重签这 18 处（见 HANDOVER §4b）。
   - 后台重传封面 / 壁纸 / 图标会把图片**内联成 base64** 写回 content.json，文件变大但同步仍有效、
     不依赖 assets、不需要部署。想瘦回 20KB 就跑同一个工具（幂等）；**只要生成了新图片文件，
     必须重新部署一次让 assets/ 上线**，只覆盖 content.json 会破图。
5. 切新链接的代码改动清单、APK 重打包签名前提、GitHub 内容共享坑，
   详见仓库 HANDOVER.md §5d，**执行迁移前务必先读**。
